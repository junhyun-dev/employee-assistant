# 직원 업무 도우미 · Employee Assistant

회사 노트북이 느려졌을 때, 교체를 요청해도 되는지 아니면 먼저 무엇을 확인해야 하는지 정책만 읽고 판단하기는 어렵다. 직원 업무 도우미는 **장비 정책을 찾아 읽고, 담당 팀에 보낼 문의 글을 준비하는 로컬 웹 앱**이다. 재택용 모니터 구입과 회사 노트북 문의를 지원한다.

예를 들어 ‘교체를 정하기 전에 무엇을 확인할지 문의하기’를 고르면, 앱은 관련 정책과 확인이 필요한 내용을 보여 주고 IT 문의 초안을 만든다. 직원은 참고 문서를 읽고 자신의 상황을 덧붙인 뒤 글을 복사할 수 있다. 입력을 바꾸거나 다시 검색해도 직접 수정한 글은 덮어쓰지 않는다.

이 프로젝트는 문서 검색을 답변에서 끝내지 않고 **근거 확인과 문의 글 작성으로 연결하는 과정**을 살펴보기 위해 만들었다. 현재는 GitLab의 공개 정책 발췌와 수동 검색 규칙, 정해진 문구를 사용한다. 실제 LLM은 연결하지 않았으며, 자유로운 질문을 해석하거나 직원의 교체 자격을 판단하지 않는다.

## 실행

Python 3.10 이상과 브라우저가 필요하다. 앱 실행에는 Python 표준 라이브러리만 사용한다. 최신 기능은 `draft-resume` 브랜치에 있으며, 기본 브랜치인 `main`은 초기 버전이다.

```sh
git clone --branch draft-resume --single-branch https://github.com/junhyun-dev/employee-assistant.git
cd employee-assistant
python3 -m employee_assistant --port 8767
```

브라우저에서 <http://127.0.0.1:8767/>을 연다. 종료하려면 터미널에서 `Ctrl+C`를 누른다. 서버는 로컬 주소에서만 접속할 수 있다. 앱 실행 중 외부 API를 호출하지 않으며, 참고 문서 링크를 직접 열 때만 GitLab 사이트로 이동한다.

## 직접 사용해 보기

앱은 모니터와 노트북 문의 예시로 시작한다. 다음 순서로 노트북 문의 하나를 작성해 볼 수 있다. 예시에는 실제 직원 정보 대신 가상의 상황을 사용한다.

1. **노트북만**을 고르고, 목적을 **교체를 정하기 전에 무엇을 확인할지 문의하기**로 바꾼다.
2. **A · 정책 읽기**에서 **예시 정보 넣기**를 누른다. 재직기간 `4년`, 느려진 상황 `지난주부터 화상회의 중`, 구매 상태 `아직 구매하지 않음`이 채워진다. 답의 **참고 문서 보기**에서 어떤 정책을 사용했는지 읽는다.
3. **문의 글 열기**로 IT 문의 글을 연다. **새 제안 비교하기**에서 두 글을 읽고, **새 제안으로 바꾸기**를 눌러 예시 정보를 반영한다. 끝에 `점검 가능한 일정을 알려 주세요.`를 직접 덧붙인다.
4. 재직기간만 `2년 10개월`로 고친다. 작성 중인 글에는 여전히 `4년`과 직접 추가한 문장이 남는다. **문의 글 복사**를 누르면 현재 입력과 복사할 글을 확인할 수 있다. **돌아가서 수정**을 눌러 글의 기간을 고친 뒤 다시 복사한다.
5. **지금 글 임시 저장**을 누르고 새로고침한다. **저장한 글 불러오기**를 선택하고 확인하면 수정했던 글이 돌아온다. 앱은 정책을 다시 검색하지만 복원한 글을 자동으로 바꾸지는 않는다.

**B · 문의 작성**으로 전환하면 같은 글을 더 넓은 편집 화면에서 고칠 수 있다. A와 B는 동일한 입력과 글을 보여 주는 두 가지 배치다.

근거가 빠졌을 때의 동작은 화면 위 **노트북 핵심 표본 제외**로 확인할 수 있다. 노트북의 새 답과 초안은 보류되지만 작성 중인 글은 남는다. **전체 표본으로 확인**을 누르면 다시 검색한다. 이 버튼은 테스트용 자료를 일부 빼는 기능이다.

## 문의를 작성할 때 할 수 있는 일

<a id="inquiry-scope"></a>
### 필요한 문의만 고르기

모니터만, 노트북만, 둘 다 중 하나를 고르면 해당 문의의 답과 참고 문서, 편집글을 볼 수 있다. 선택에서 빠진 글은 지우지 않으며 다시 선택하면 그대로 돌아온다. 임시 저장에는 화면에 보이지 않는 글도 함께 들어간다.

### 아는 내용부터 적기

노트북 문의는 교체 전에 무엇을 확인할지 묻는 글과 교체 절차를 묻는 글을 나누어 제공한다. 재직기간이나 구매 상태를 아직 입력하지 않아도 초안을 만들 수 있다. 빈 정보는 문장에서 생략하고, 구매 여부를 모른다고 직접 선택한 경우에는 그 사실을 글에 남긴다.

모니터 문의에서는 승인 품목과 일반 수당 안내를 보여 준다. 개인에게 적용되는 수당이나 남은 금액은 담당 팀에 확인하도록 문의 글에 담는다. 노트북용으로 입력한 재직기간 등을 모니터 초안에 자동으로 넣지는 않는다.

<a id="진행-중-답에서-참고한-정책-절로-이동하기"></a>
<a id="답에서-참고한-정책-절로-이동하기"></a>
### 답에 사용한 문서 읽기

**참고 문서 보기**를 누르면 해당 답에 연결된 정책 절의 원문과 공개 링크를 볼 수 있다. **답으로 돌아가기**로 읽던 위치에 돌아온다. 필요한 정책 절이 없으면 그 문의의 새 답과 초안을 보류한다. 직원이 적지 않은 정보와 답을 뒷받침할 문서가 없는 경우를 다르게 처리한다.

<a id="진행-중-새-제안을-반영하기-전에-비교하기"></a>
<a id="새-제안을-반영하기-전에-비교하기"></a>
### 새 초안을 비교하고 글 가져가기

새 제안과 작성 중인 글을 나란히 보고, 빠지는 내용은 취소선으로, 추가되는 내용은 밑줄로 확인한다. **현재 글 유지**로 취소하거나 **새 제안으로 바꾸기**로 글 전체를 교체한다. 직접 추가한 요청도 교체 과정에서 사라질 수 있으므로 자동으로 합치지 않는다. 긴 글에서는 세부 표시 대신 두 글 전체를 보여 준다.

평소에는 수정한 글을 바로 복사할 수 있다. 입력이나 근거가 바뀌었거나 검색에 실패한 경우에는 복사 전에 다시 확인할 내용을 보여 준다. 앱은 글과 상태의 변경 여부를 확인하고, 문장이 맞는지는 사람이 읽고 판단한다. 실제 문의 발송은 지원하지 않는다.

### 저장하고 이어 쓰기

**지금 글 임시 저장**을 눌렀을 때만 선택한 문의와 목적, 입력한 내용, 두 편집글을 브라우저에 한 건 저장한다. 마지막 저장 후 24시간 안에 불러올 수 있으며, 읽거나 복원해도 보관 시간이 늘어나지 않는다. 만료된 내용은 앱이 다시 접근할 때 삭제한다. 자동저장은 아니므로 저장 이후에 고친 부분은 다시 저장해야 한다.

저장본을 찾으려면 같은 브라우저 프로필과 주소·포트를 사용해야 한다. 다른 탭이 저장본을 먼저 바꿨다면 오래된 내용으로 덮어쓰지 않도록 알려 준다. **새 문의**는 현재 화면만 초기화하고, **저장본 삭제**는 저장본만 지운다.

**로그인이나 사용자별 저장 보호는 없다.** 같은 브라우저를 공유하는 사람도 글을 불러올 수 있으므로 공개 예시로 사용하고, 회사 정보나 민감한 내용을 저장하지 않는 편이 좋다. 서버 백업도 제공하지 않는다. 미저장 수정이 있으면 브라우저에 이탈 확인을 요청하지만, 모바일 강제 종료 등에서는 확인창이 뜨지 않을 수 있다.

## 설계와 코드 읽기

### 검색한 문서가 있다고 곧바로 답하지 않는다

[flow.py](employee_assistant/flow.py)는 문의 종류에 맞춰 공개 표본을 키워드로 검색하고, 답에 필요한 정책 절이 있는지 확인한다. 선택하지 않은 문의와 선택했지만 근거가 부족한 문의를 구별한다. 예를 들어 모니터만 선택했다면 노트북 절이 없어도 모니터 안내는 계속할 수 있다. 이 판단은 미리 정한 규칙에 따르며 임의 질문의 근거가 충분한지 알아내는 기능은 아니다.

### 새 제안과 직원이 고친 글을 따로 둔다

재직기간을 고쳤다고 초안을 즉시 교체하면 직원이 덧붙인 일정 요청까지 잃는다. [app.js](web/app.js)는 입력, 새 제안, 편집글을 따로 관리한다. 검색 응답이 늦게 도착하거나 비교창을 연 뒤 입력이 바뀌면 오래된 제안을 적용하지 않는다. [text_diff.js](web/text_diff.js)는 비교할 두 글의 문자 차이를 계산한다.

[draft_store.js](web/draft_store.js)는 IndexedDB에서 저장본을 읽었을 때의 버전과 현재 버전을 한 트랜잭션 안에서 비교한 뒤 저장·삭제한다. 이전 형식의 저장본도 읽을 수 있으며 복원만으로 원래 내용이나 저장 시각을 다시 쓰지 않는다. 지원하지 않는 형식은 자동으로 지우지 않는다. 관련 사례는 [저장·복원 검사](tests/draft_resume_flow.py)에 있다.

### 모델을 연결할 자리와 현재 실행을 구별한다

[server.py](employee_assistant/server.py)는 로컬 HTTP 요청과 입력 형식을 처리한다. 현재 화면의 답과 초안은 `flow.py`의 규칙으로 만든다. 별도의 [model_contract.py](employee_assistant/model_contract.py)는 향후 모델에 전달할 입력과 반환 형식을 검사하는 코드다. 요청에 없는 근거 ID, 오래된 입력으로 만든 제안, 근거가 부족한데 작성한 답 등을 거부한다. 실제 모델 호출이나 답 문장의 의미 정확성 검사는 구현하지 않았다.

## 검증

단위 테스트는 별도 패키지 없이 실행할 수 있다.

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

현재 38개 테스트가 문의 선택, 빠진 입력, HTTP 오류 처리, 모델 입력·반환 형식 등을 다룬다. 모델 관련 테스트는 실제 생성 대신 합성 반환값을 사용한다.

[브라우저 테스트](tests/browser_flow.py)는 글 편집과 제안 비교, 복사, 근거 누락, 늦은 응답, A/B 화면과 모바일 표시를 확인한다. [저장 테스트](tests/draft_resume_flow.py)는 재열기, 두 탭의 동시 수정, 저장 실패, 이전 형식 복원 등을 다룬다. 테스트에는 별도 브라우저 프로필과 가상 직원 정보를 사용한다.

## 현재 한계

이 앱은 고정된 장비 문의를 다루는 포트폴리오 프로젝트다. 전체 정책 검색이나 최신 정책 자동 갱신, 개인 수당·승인 상태 조회, 실제 발송과 기업 배포를 지원하지 않는다. 테스트 통과가 실제 직원의 사용성이나 정책 해석의 정확성을 입증하는 것은 아니다. 외부 모델을 연결한 비교 실험은 아직 진행하지 않았다.
